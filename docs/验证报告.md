## Conductor 工作区

## Windsurf / Devin Desktop 与 Agent 客户端

- 未命名工作区在编辑器默认数据布局下直接识别。合成用例覆盖工作区文件移除后重扫、远程工作区、排除目录、文件与目录符号链接和其他编辑器的同名配置。手动扫描后的隔离请求确认配置仍完整保留。
- 已保存的多根工作区使用含注释及尾逗号的 JSONC 样本，覆盖相对路径、绝对路径、文件 URI、去重、远程记录、外部配置授权、链接、损坏配置和配置变更。隔离清理请求还验证了构建目录里的 `.code-workspace` 仍会保留。
- 只读核对 Devin Desktop `3.14.30833` 的官方镜像摘要、签名、应用标识和 IDE 工作区写入结构。合成工作区覆盖新旧目录、中文路径、远程 URI、链接和缓存失效。隔离请求验证工作区数据库和 Cascade 会话都保留在原位。
- Pi `1.6.1` 在临时数据目录使用回环地址的模拟模型完成一轮对话，生成真实 v3 日志。既白自动关联日志中的中文目录，归属 Pi 并标为保留。
- DeepSeek Harness `0.2.2-rc.5` 的官方签名镜像已核对 `com.deepseek.dsh`。真实桌面和 CLI 会话生成仍待验证。压缩会话继续使用隔离样本回归。

## Agent 扩展第三批

本机隔离套件运行 211 项，209 项通过。两项分别需要官方 VS Code 归档和大小写敏感卷；在当前大小写不敏感卷上，Docker 虚拟磁盘的路径别名保护通过。Swift 构建和原生 Store 联调通过。

模型用模拟 HTTP 响应验证固定修订、公开来源、摘要错误、响应中断、目录权限撤回、同名文件保护和原缓存缺失后的重新获取。MCP 用隔离工作区验证逐项清单、过期与重复提交、跨范围选择拒绝、新增工程引用拦截，以及隔离后恢复。开发缓存和媒体样本验证了布局判定、受保护文件、硬链接计量和已知引用。实际模型工具导入、Agent 客户端兼容性和同机竞品数据分开验收。[适配覆盖矩阵](Agent扩展计划.md)

本机 100 个合成工程、10 万文件，首次快速盘点中位数 15.01 秒，已建索引的目录查询 P95 为 0.57 毫秒。计量范围为引擎，含首次盘点的状态写入。

## Agent 扩展第二批

隔离引擎套件共运行 152 项，151 项通过，依赖可选 VS Code 官方归档的一项另由托管 Mac 验证。新增回归涵盖 8 个工具家族的元数据、配置变更后的缓存失效、OpenClaw 工程跨目录素材、ComfyUI 自定义目录及 `.bin` 依赖、模型接口模拟响应、会话事件去重及授权撤回。在任务隔离批次提交后模拟中断，收尾单可从日志重新关联该批次，重试任务关闭不会再次移动文件。原生 Store 联调和 Swift 构建也单独通过。

模型加载状态在测试中使用模拟本机服务。实际运行版本、配置变体和 Latent 同机对标仍按覆盖矩阵验收。[适配覆盖矩阵](Agent扩展计划.md)

在 10 万文件的同机合成盘点中，目录级归属复用将三次首次盘点的中位数从 17.13 秒降至 15.85 秒。与首批记录的旧版基线 15.47 秒相比增加约 2.5%。缓存目录的引擎查询 P95 为 0.88 毫秒。计时范围包含扫描和状态写入，完整窗口响应另行记录。

## Agent 扩展首批

合成元数据覆盖 6 种 Agent 的相关工作区，以及当前安装核验支持的应用包和扩展清单。关键回归覆盖同一工程被多个 Agent 使用、跨存储硬链接去重、外部目录授权与撤销、无效路径、会话索引缓存，以及识别到的工具数据无法加入清理执行批次。

在同一台 Apple Silicon Mac 的隔离环境里，用相同的 100 个 Codex 工程、100,000 个文件和空白配置做三次首次快速盘点。既白旧版（`5624614`）的中位数为 15.47 秒，首批开发分支初测为 14.87 秒，减少 3.8%。已经建好索引后的 100 次目录查询，引擎 P95 为 0.66 毫秒。此次测量包括引擎扫描和状态写入。Swift 窗口渲染、真实工具数据和 Latent 的同机对标分别验收。可用 `./scripts/test-isolated.sh --benchmark-agent-inventory` 复测。

## 扫描与界面响应

在同一台 Apple Silicon Mac 上，用 72 个合成 Codex 工程、18,432 个文件测试首次盘点。优化目录排除匹配和状态序列化后，服务端耗时从 55.0 秒降到 2.6 秒，工程数、文件数和分配字节数保持一致。可用 `./scripts/test-isolated.sh --benchmark` 复测。快速启动会读取近期会话的开头，深度扫描可继续发现会话后续更换过的工作目录。

将 58,000 条合成文件记录交给 Swift 汇总函数，分别执行 9 次并取中位数。旧版切到 Agent 工作区时现场汇总约 234 毫秒，应用排行约 23 毫秒，首页图例状态变化时重算候选数约 14 毫秒。新版将汇总移到后台，每份扫描结果只计算一次，三条界面路径读取缓存或重排汇总的中位数均低于 0.1 毫秒。此处计量的是数据处理，窗口绘制和真实磁盘读取需要单独测量。

预览版 `v0.1.0-dev.3` 的 62 项用例均在提供官方归档后通过。托管 Mac 还验证了原生启动、默认扫描、独立演练以及真实 VS Code 清理后的离线重启。[验证日志](https://github.com/Moosphan/lumen/actions/runs/45382119174)

## 环境与操作边界

本地开发验收使用 Apple Silicon、macOS 14.1.2、Xcode 15.4、Swift 5.10 和系统 Python 3.9.6。引擎和 Swift 联调测试分别创建新的临时目录和状态库。应用使用演练专属废纸篓。文件操作回归使用 macOS sandbox-exec，禁止网络及临时工作区外的写入，并在测试开头检验保护规则。没有对真实用户 Library、Downloads、用户废纸篓或已安装的应用执行清理，也未安装后台作业。

### 官方应用包实测

从微软官方更新端点取得 VS Code 1.95.3 ARM64 归档，在临时目录展开。核对 Microsoft Team ID、bundle ID 和代码签名后对该副本执行卸载隔离，再原位恢复并重新检查元数据清单和签名。归档 SHA-256 为 `fe01f564777afb75703e748ada00f1204f0495be54947d6ffb513e5a5eb16a08`，大小 135,066,855 B。归档与展开的第三方应用未纳入本仓库。本用例没有启动 VS Code。[微软固定版本入口](https://update.code.visualstudio.com/1.95.3/darwin-arm64/stable)

独立的真实会话测试在一次性托管 Mac 上启动 VS Code，编辑并保存文稿，确认编辑器已产生本地历史，然后正常退出。测试将一份真实主日志调整到过期时间，并建立十个较新的保留目录。既白通过生产扫描和直接清理入口移除选定日志。第二次离线启动时，编辑器读出了同一份文稿、历史修订、工作区设置、扩展状态及离线素材，历史内容哈希与清理前一致。测试使用合成的离线工作区，真实账户登录态单独列入发布验收。[真实编辑器测试记录](https://github.com/Moosphan/lumen/actions/runs/45361897190)

### 原生窗口与磁盘扫描基线

GitHub 托管 macOS 15 的辅助功能测试启动打包好的 Lumen.app，读取实际窗口标题，从空工作区点击「创建演练样本」，核对授权目录，触发重扫并验证扫描标识改变，最后返回原工作区并核实授权仍为空。工作流同时输出可下载的原生窗口截图与开发包。[发布版本原生窗口验收日志](https://github.com/Moosphan/lumen/actions/runs/45361897190)

在上述本机环境中用 `./scripts/test-isolated.sh --benchmark` 生成 100 个临时目录，每个目录包含 100 份各自独立的 64 B 文件，同一内容重复出现在不同目录中。扫描器单次测量结果如下。

| 模式 | 索引文件数 | 耗时 | 内容哈希读取 | 哈希复用 | 进程累计峰值内存 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 快速盘点 | 10,000 | 0.99 s | 0 | 0 | 40.5 MiB |
| 首次深度盘点 | 10,000 | 2.15 s | 10,000 | 0 | 47.6 MiB |
| 同目录深度重扫 | 10,000 | 2.15 s | 0 | 10,000 | 55.1 MiB |

此测量只涵盖扫描引擎，未计入 UI 绘制与结果持久化。重扫复用了全部哈希，同时仍逐项检查文件身份。大媒体、多卷、百万文件规模需要各自的测量。
